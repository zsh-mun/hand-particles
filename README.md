# 手势粒子 · 张开与闭合

用手机前置摄像头识别手势：**张开手指，沙尘 / 星系 / 水滴 / 萤火向外炸开；握紧拳头，它们被吸回掌心。**
伸出两只手并且都张开，粒子还会在两掌之间拉成一座桥。

是一个**纯静态网页**：没有后端、没有构建步骤、不依赖任何 CDN。
手部关键点识别用的是 MediaPipe HandLandmarker，库和模型都已经放在 `vendor/` 里（约 27 MB），
所以第一次打开之后就不再需要联网（大文件会缓存 7 天）。

`preview/` 里有几张用演示模式（`?demo=1&pose=…&ff=…`）拍的效果图，可以先看看大概长什么样。

> 在线地址：`https://<你的用户名>.github.io/<仓库名>/` ← 部署完之后把这一行改成你自己的真实地址

---

## 一、先在电脑上跑起来

```bash
cd hand-particles
node serve.mjs
```

然后浏览器打开 <http://localhost:8787>。

> 电脑上用 `localhost` 是安全的，可以直接点「开启摄像头」，用你自己的手试。
> 只想看效果、不想开摄像头的话，点「先看看效果（演示模式）」，
> 屏幕上会有一只手自动开合，走的是和真实手完全一样的识别/物理链路。

不要双击 `index.html` 用 `file://` 打开：ES module 和 wasm 都会被浏览器的同源策略拦掉。

## 二、怎么在手机上真的用起来（关键一步）

**手机浏览器只允许 HTTPS 页面访问摄像头**（`localhost` 除外，但手机上的 localhost 是手机自己）。
所以想用摄像头，必须给手机一个 https 地址。下面四种方案按需选：

### 方案 A：临时隧道（最快，1 分钟）

```bash
# 先启动本地服务
node serve.mjs

# 另开一个终端，用 cloudflared 开一条临时 https 隧道
cloudflared tunnel --url http://localhost:8787
# 它会打印一个 https://xxxx.trycloudflare.com 的地址，手机浏览器打开这个地址
```

ngrok 同理：`ngrok http 8787`。手机和电脑不需要在同一个 WiFi。

### 方案 B：GitHub Pages（最稳，也是推荐做法）

这整个目录就是一份静态站点，仓库根目录即站点根目录。**仓库必须是公开（Public）**的，
因为免费账号的 Pages 只支持公开仓库（代码公开，但网站完全在浏览器里跑，
摄像头画面不会上传到任何地方）。

1. 在 GitHub 上建一个仓库（例如 `hand-particles`）。已经有仓库的话，跳过这步，
   把下面的 `<你的用户名>/<仓库名>` 换成你的。
2. 把本地仓库推上去（在本目录执行，只需一次）：

   ```bash
   git remote add origin https://github.com/<你的用户名>/<仓库名>.git
   git push -u origin main
   ```

   第一次会弹出 GitHub 授权窗口（Windows 上用的是 Git Credential Manager），点一下就行。
   之后同步改动只需要 `git add -A && git commit -m "..." && git push`。
3. 仓库页面 → **Settings → Pages**：Source 选 `Deploy from a branch`，
   Branch 选 `main`、目录选 `/ (root)`，Save。
4. 等 1~2 分钟，访问 `https://<你的用户名>.github.io/<仓库名>/`。

   如果仓库名正好是 `<你的用户名>.github.io`，那地址就是 `https://<你的用户名>.github.io/`。

`.nojekyll` 已经放进去了（避免 GitHub 用 Jekyll 处理静态文件），
`sw.js` 是 Service Worker：Pages 对静态资源的缓存只有 10 分钟且不能自定义，
它会把 17 MB 的 wasm + 模型存到浏览器本地，**第二次打开基本秒开，之后甚至能离线用**。

### 方案 C：其它静态托管

同一个目录直接拖给 Vercel / Netlify / Cloudflare Pages 也可以，都是免费 https。
用 Nginx 的话注意 `.wasm` 要返回 `application/wasm`。

### 方案 D：局域网 http（只适合 Android Chrome 临时试）

先 `node serve.mjs`，手机和电脑连同一个 WiFi，手机访问 `http://<电脑IP>:8787`。
默认打不开摄像头，需要在电脑上给 Chrome 加白名单：

1. 地址栏输入 `chrome://flags/#unsafely-treat-insecure-origin-as-secure`
2. 填入 `http://192.168.x.x:8787`（换成实际的电脑 IP，就是 `serve.mjs` 启动时打印的那个）
3. 重启 Chrome

**iPhone / Safari 没有这个后门**，必须用方案 A 或 B；而且 iOS 上还要求摄像头页面在被点开的那个标签页里，
不能从别的 App 内嵌浏览器里直接调用。

### 加到主屏幕

用 https 打开后，Safari「分享 → 添加到主屏幕」或 Chrome「⋮ → 添加到主屏幕」，
会以全屏（无地址栏）方式运行，体验更像一个 App。

## 三、屏幕上的操作

| 操作 | 效果 |
| --- | --- |
| 张开手指（五指伸直） | 粒子向外炸开，半径随张开度连续变化；张开越快，外抛越猛 |
| 握紧拳头 | 粒子被吸回掌心，同时带一点旋涡 |
| 手在画面里挥动 | 带起"风"，粒子顺着挥手方向偏 |
| 两只手都张开 | 两掌之间形成粒子桥；两只手各自的开合独立生效 |
| 手离开画面 | 粒子重新变成缓慢漂浮的尘埃 / 星尘（不会突然消失） |
| 底部按钮 | 切换 沙尘 / 星系 / 水滴 / 萤火 |
| ⚙ | 调灵敏度、粒子数量、背景暗度、流畅度、前后摄像头、镜像、显示骨架 |

上手小技巧：**手离摄像头半米左右、整个手在画面内、背景光线别太暗**，识别最稳。
顶部左边的两条进度条就是两只手实时的"张开度"读数，
如果握拳时它没归零、张开时没满格，就去 ⚙ 里调「手势灵敏度」。

## 四、目录结构

```
hand-particles/
├─ index.html            页面结构 + 全部样式
├─ app.js                主程序：摄像头 → 识别 → 手势 → 粒子 → 绘制 + 全部 UI 逻辑
├─ src/
│  ├─ gesture.js         纯函数：21 个关键点 → 张开度/掌心/捏合度；含平滑与丢失滑行
│  ├─ particles.js       粒子场：弹簧/阻尼/旋涡/风/重力 + 四种模式的参数表
│  └─ synthetic.js       程序化生成的手（演示模式 + 自检用）
├─ vendor/               本地化的 MediaPipe（不依赖 CDN，中国大陆网络友好）
│  ├─ vision_bundle.js
│  ├─ wasm/              SIMD 与 非 SIMD 两套 wasm（老机型自动回退）
│  └─ models/hand_landmarker.task
├─ serve.mjs             本地静态服务器（正确的 MIME，手机可访问）
├─ manifest.json         加到主屏幕用的清单
└─ icon-192/512/180.png  图标
```

### 调试用的 URL 参数

这些参数既是给我自己排查问题用的，也方便你对照着调效果：

| 参数 | 说明 |
| --- | --- |
| `?demo=1` | 演示模式（合成手，不用摄像头） |
| `&pose=0.9` | 固定手势：0 = 握拳，1 = 完全张开 |
| `&ff=2.5` | 先以固定步长快进 2.5 秒物理再定格（截图 / 录屏可复现） |
| `&mode=galaxy` | `sand` / `galaxy` / `water` / `firefly` |
| `&q=low\|balanced\|high` | 省电 / 均衡 / 流畅 |
| `&skel=1` | 显示手部骨架 |
| `&bare=1` | 纯净模式，隐藏所有 UI 叠层（录屏用） |
| `&probe=1` | 把关键数值（视口、吸引子、粒子统计、各层位置）打在页面上 |
| `&selftest=1` | 只加载识别模型并跑一次推理，结果写在页面上并回传给本地服务器 |
| `&hide=panel,vignette` | 临时隐藏某几层（排查渲染问题） |

例：`http://localhost:8787/?mode=water&demo=1&pose=0.95&ff=2.5` 就是一张
"水滴完全张开"的定格图，每次跑都一样。

## 五、它是怎么工作的

```
getUserMedia(前置摄像头)
  └─ MediaPipe HandLandmarker  →  两手各 21 个关键点（归一化坐标）
       └─ gesture.js：把指尖到手腕的距离除以手掌尺寸，得到每根手指的开合度，
          加权平均成 openness（0=握拳，1=张开），再做时间平滑与速度估计
            └─ 每只手变成一个"吸引子"：21 个锚点 + 一个由 openness 驱动的半径
                 └─ particles.js：每个粒子挂在最近锚点上，
                    弹簧拉向"锚点 + 极坐标偏移"，张开时给一个向外的冲量，
                    握拳时给一个切向旋涡，外加重力/风/地面软墙
                      └─ canvas 2D 绘制（预渲染精灵 + 拖尾淡出）
```

几个刻意的设计：

- **识别在 18~30 Hz，渲染在 60 Hz**：关键点带平滑和速度估计，所以低检测率下手势动作依然顺滑。
- **粒子云半径由张开度连续驱动**，不是"张开/握拳"两个状态硬切，所以半开状态也好看。
- **丢失宽限 0.14 秒**：识别偶尔漏一帧不会让粒子散掉；真的离开画面后 0.5 秒内淡出成漂浮尘埃。
- **单手/双手/无手都能跑**：无手时粒子回到各自的"老家"慢慢漂，画面永远是活的。
- **自动降级**：连续掉帧会自动减少粒子数量（最多降 3 次），保证手机上不卡成幻灯片。

## 六、想改效果就去改参数

`src/particles.js` 顶部的 `MODES` 就是四种材质的参数表，直接改数字即可：

| 参数 | 作用 |
| --- | --- |
| `spring` / `zeta` | 弹簧刚度和阻尼比：越大越"跟手"，`zeta` 越小越飘、越容易过冲 |
| `rIn` / `rOut` | 握拳 / 张开时的粒子云半径（× 手掌尺寸） |
| `kick` | 张开瞬间向外冲量的强度（决定"炸开"有多猛） |
| `closeSwirl` / `orbit` | 握拳旋涡、常态环绕速度（星系靠它自转） |
| `gravity` / `wind` / `drag` | 重力、挥手的风、空气阻力 |
| `spiral` | 螺旋臂（星系专用） |
| `sizeMin/Max`、`colors`、`blend`、`alpha`、`twinkle` | 外观 |
| `fadeTau` | 拖尾残留时长 |

想加一种新材质（花瓣、火焰……）：在 `MODES` 里加一项、在 `app.js` 的 `LOOK` 里配一组颜色，
底部按钮会自动多出一个。`app.js` 里的 `sprite()` 负责生成粒子贴图，照着加一种画法即可。

## 七、已知限制

- 手要有一定大小：手离镜头太远、或者只有一两根手指入镜时，关键点会飘。
- 强逆光/很暗的环境识别会明显变差（这是模型本身的限制，不是网页的）。
- 手臂快速大幅挥动、手被遮挡时，MediaPipe 会重新检测，会有轻微跳动（已做平滑，但极端情况下仍可见）。
- 首次打开要下 27 MB（模型 + wasm）。方案 B 上的 `sw.js` 会把它存到浏览器本地，之后基本秒开。
- 极老机型的 WebAssembly 没有 SIMD，会自动回退到非 SIMD 的 wasm，识别会慢一些。
